# 온보딩 연령별 스토리 난이도 설계

## 목표

비주얼노벨 온보딩에서 아이가 직접 입력한 나이로 같은 분기 구조의 `easy` 또는 `hard` 원고를 선택한다. 선택한 난이도는 이야기 세션에 저장되어 새로고침, 진행 복원, 다시 읽기에서도 유지된다.

## 사용자 흐름과 문구

질문 순서는 다음과 같다.

1. 이름: `늦었다, 늦었어! 그런데 넌 누구니? 이름을 알려 줘.`
2. 나이: `너는 몇 살이야?`
   - 1~9를 입력하면 `easy`
   - 10 이상의 정수를 입력하면 `hard`
3. 간식: `모험 가방에 어떤 간식을 넣을까?`
4. 친구: `마지막 질문이야. 함께 모험할 친구는 누구야?`
5. 최종 확인 화면에서 이름, 나이, 간식, 친구를 확인하고 `이대로 출발!`을 누른다.

나이는 `type="number"`, `min="1"`, `step="1"`, `inputmode="numeric"` 입력으로 직접 받는다. 빈 값, 0, 음수, 소수, 문자는 `나이는 1 이상의 숫자로 입력해 줘.`를 입력 아래 표시하고 나이 질문에 머문다. 폼은 브라우저별 기본 검증 차이에 의존하지 않고 앱 검증 결과를 항상 표시한다. 친구 질문 이후의 확인과 이야기 시작 방식은 기존 로직을 유지한다.

## 상태와 데이터 흐름

- 진행 중인 온보딩에는 정수 `age`와 스토리 `level`을 함께 보관한다.
- 유효하지 않은 나이 입력은 온보딩 상태의 `validationError`에 기록하고, 유효한 답변을 받으면 오류를 제거한다.
- 이야기 시작 시 `level`을 세션의 최상위 필드에 저장한다.
- 지원 레벨은 `easy`, `hard` 두 값으로 제한한다.
- 레벨이 없거나 잘못된 기존 세션은 생성 번들의 기본값인 `hard`로 정규화한다.
- 이름, 간식, 친구는 기존 개인화 슬롯 계약을 그대로 사용하며 난이도는 개인화 슬롯에 섞지 않는다.

## 스토리 런타임

`story-data.js`는 레벨별 런타임을 한 번씩 만들고, 요청한 레벨에 맞는 런타임을 반환한다. 앱의 장면, 조건부 장면, 결말, 낱말 조회는 현재 세션의 레벨을 사용한다. 이 구조로 전역 런타임을 변경하거나 페이지를 새로고침하지 않고 원고를 전환한다.

## 저장과 호환성

- 테스트 모드의 진행 중 온보딩 저장 데이터에도 숫자 나이 및 레벨 선택을 포함한다.
- 완성된 이야기 세션에는 `level`을 저장한다.
- 이전 버전의 `ageGroup` 값은 진행 중 온보딩 복원 및 확인 화면에서 계속 표시한다. 새 답변은 `age`만 저장한다.
- 기존 세션과 기존 테스트 기록은 `level`이 없으면 `hard`로 계속 열린다.
- 다시 시작하거나 다른 결말을 볼 때 현재 세션의 레벨은 바뀌지 않는다.

## 검증

- 온보딩 질문이 이름, 나이, 간식, 친구, 확인 순서로 진행되는지 검증한다.
- 경계값 1, 9, 10과 더 큰 정수가 각각 올바른 레벨로 변환되는지 검증한다.
- 빈 값, 0, 음수, 소수, 문자가 오류 안내를 표시하고 나이 단계에 머무는지 검증한다.
- 나이 입력이 숫자 키패드 힌트와 정수 제약을 제공하는지 검증한다.
- 확인 화면에 입력한 나이가 `9살`처럼 표시되는지 검증한다.
- 완료한 온보딩의 레벨이 세션과 테스트 기록에 저장되는지 검증한다.
- 저장된 세션 복원과 다시 시작에서 레벨이 유지되는지 검증한다.
- 같은 장면 ID가 선택한 레벨의 문장과 낱말로 렌더링되는지 검증한다.
- 레벨이 없는 기존 세션이 `hard`로 복원되는지 검증한다.

## 범위 제외

- 이야기 진행 중 난이도 변경
- 생년월일 수집
- `easy`와 `hard` 사이의 분기 구조 변경
