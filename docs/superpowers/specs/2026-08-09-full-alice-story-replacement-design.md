# 앨리스 전체 스토리 교체 설계

## 목표

`experiment/alice-ui-variants` 브랜치의 3결말 MVP를 첨부된 「너의 선택으로 열리는 앨리스의 이상한 나라」 마스터 원고 v2.0/v2.1 기준 전체 분기 이야기로 교체한다.

모든 UI 변형에서 삽화는 실제 그림 대신 동일한 회색 플레이스홀더를 사용한다. 플레이스홀더 중앙에는 나중에 교체할 삽화의 이미지 키를 정확히 표시한다.

## 원고 범위

다음 17개 텍스트 노드를 모두 구현한다.

- 시작·경로 선택: `S00`, `S01`, `S02`
- 만남: `A1`, `A2`, `A3`, `B1`, `B2`, `B3`
- 공통 수렴부: `C1`, `C2`
- 결말: `E1`, `E2`, `E3`, `E4`, `E5`, `E6`

분기 구조는 다음과 같다.

```text
S00
├─ S01 ─ A1/A2/A3 ─┐
└─ S02 ─ B1/B2/B3 ─┴─ C1 ─ C2 ─ E1/E2/E3/E4/E5/E6
```

만남 노드에서 선택한 대답은 원고의 `{CHILD_INPUT}`에 사용한다. 만남 노드는 바로 결말로 이동하지 않고 모두 `C1`으로 수렴한다.

## 조건과 결말 결정

세션의 현재 실행 기록에 다음 이야기 상태를 저장한다.

- `encounterId`: `A1`~`B3` 중 선택한 만남. 최종 결말을 결정한다.
- `gardenEntry`: `C1`에서 선택한 `SECRET` 또는 `GUEST`.
- `endingVariation`: `C2`에서 선택한 `TRUTH`, `SHIELD`, `TURN`.

`C1`은 현재 실행 경로에 `A1` 또는 `B1`이 있으면 체셔 고양이와 재회하는 문장을, 그렇지 않으면 처음 만나는 문장을 렌더링한다.

`C2`는 `gardenEntry`에 따라 담장 뒤 또는 정문 진입 문장을 렌더링한다. 세 결말 선택지는 모두 항상 표시한다.

`C2` 선택 후 `encounterId`를 다음과 같이 결말에 연결한다.

| 만남 | 결말 |
|---|---|
| `A1` | `E1` 호기심 |
| `A2` | `E2` 신중함 |
| `A3` | `E3` 유쾌함 |
| `B1` | `E4` 침착함 |
| `B2` | `E5` 자기확신 |
| `B3` | `E6` 친화력 |

각 결말은 `endingVariation`에 맞는 공통 변주 블록과 결말별 조정 문장, 부모 노트 한 줄을 결합한다. 따라서 도달 가능한 결말은 6종이고 각 결말은 3개 변주를 갖는다.

## 개인화

마스터 원고 v2.1에 맞춰 `{COLOR}`를 제거한다.

- 유지: `{HERO}`, `{TREAT}`, `{PET}`
- 제거: `COLOR` 기본값, 허용 목록, 온보딩 질문, 템플릿 사용
- 토끼 대화형 온보딩은 이름 → 친구 → 간식의 3문항으로 유지한다.

기존 저장 데이터에 `COLOR`가 있어도 읽기는 실패하지 않아야 한다. 새로 저장하는 슬롯에는 세 값만 포함한다.

## 삽화 플레이스홀더

모든 이야기·결말 화면은 실제 SVG, 캐릭터 스프라이트, CSS 도형을 사용하지 않는다. 공통 렌더러가 다음 형태의 삽화 영역을 만든다.

- 중간 회색 배경
- 충분한 명도 대비의 이미지 키 텍스트
- 이미지 키를 접근 가능한 레이블로도 제공
- UI 변형과 화면 크기에 관계없이 같은 키를 표시

원고에 정의된 키를 사용한다.

| 노드 | 이미지 키 |
|---|---|
| `S00` | `start_rabbit_hole` |
| `S01` | `door_shrink` |
| `S02` | `cake_grow` |
| `A1` | `door_cat_meet` |
| `A2` | `door_caterpillar_meet` |
| `A3` | `door_hatter_meet` |
| `B1` | `cake_cat_meet` |
| `B2` | `cake_caterpillar_meet` |
| `B3` | `cake_hatter_meet` |
| `C1` | `mist_hill_grin` |
| `C2` (작아진 경로) | `queen_garden_trial_small` |
| `C2` (커진 경로) | `queen_garden_trial_big` |
| `E1` | `end_curiosity` |
| `E2` | `end_prudence` |
| `E3` | `end_cheer` |
| `E4` | `end_composure` |
| `E5` | `end_selftrust` |
| `E6` | `end_warmth` |

`C2`의 키는 현재 실행의 `encounterId`가 `A`로 시작하면 `small`, `B`로 시작하면 `big`을 선택한다.

기존 `assets/visual-novel` 파일은 더 이상 런타임에서 참조하지 않는다. 파일 자체를 삭제하는 것은 이번 범위에 필요하지 않다.

## 데이터와 렌더링 경계

`story-data.js`는 원고 본문, 선택지, 낱말, 삽화 키, 조건별 문장과 변주 블록을 보관한다. 세션 모듈은 현재 실행의 이야기 상태를 기록한다. 앱 상태 전이는 선택 메타데이터를 세션에 적용하고, 렌더러는 세션을 바탕으로 조건부 본문·결말·삽화 키를 계산한다.

세 UI 변형은 동일한 스토리 데이터와 상태 전이를 소비한다. 각 변형이 별도의 삽화 매니페스트를 갖지 않도록 공통 플레이스홀더 렌더링 계약을 사용한다.

## 저장 호환성과 오류 처리

- 저장 세션이 현재 필수 구조를 만족하지 않으면 복구 화면을 표시한다.
- 이전 3결말 실행 기록과 `endingsSeen`은 읽을 수 있지만 새 실행은 전체 그래프 규칙을 따른다.
- 필수 이야기 상태가 없이 `C1`, `C2`, 결말로 복원되면 복구 화면으로 이동한다.
- 알 수 없는 장면, 선택 메타데이터, 이미지 키는 그래프 테스트에서 실패시킨다.

## 테스트

자동 테스트로 다음을 검증한다.

- 17개 노드가 존재하고 모든 참조가 유효하다.
- 여섯 만남에서 각각 대응하는 여섯 결말에 도달할 수 있다.
- 모든 만남이 `C1`, `C2`를 통과한다.
- 각 결말에서 `TRUTH`, `SHIELD`, `TURN` 세 변주가 렌더링된다.
- `SECRET/GUEST`와 고양이 재회/첫 만남 문장이 올바르게 바뀐다.
- `{COLOR}`가 데이터와 온보딩에서 제거된다.
- 모든 노드가 유효한 이미지 키를 가지며 `C2`는 경로 크기에 맞는 키를 고른다.
- current, minimal-text, visual-novel UI 모두 회색 플레이스홀더 중앙에 이미지 키를 출력한다.
- 기존 실제 SVG와 캐릭터 스프라이트는 런타임 HTML에 나타나지 않는다.
- 전체 Node 테스트 스위트가 통과한다.

수동 확인은 모바일 폭에서 세 UI 변형의 플레이스홀더, 긴 원고의 읽기 흐름, 전체 6개 결말의 재시작 동작을 확인한다.

## 범위 밖

- 실제 삽화 제작 또는 첨부
- 원고의 쉬움·어려움 별도 판본 생성
- 실시간 AI 자유 입력
- 원격 분석 전송
- 기존 UI 변형의 전면 재디자인
