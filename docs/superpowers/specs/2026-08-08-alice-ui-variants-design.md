# 앨리스 UI 비교판 설계

## 목표

현재 `alice-branching-mvp`의 이야기, 개인화, 분기, 낱말, 결말 수집, 로컬 세션 동작을 유지하면서 내부 판단용 UI 세 가지를 같은 장면에서 즉시 비교할 수 있게 한다.

- `current`: 현재 이야기책 UI 기준선
- `visual-novel`: 풀블리드 장면과 하단 대화창 중심 UI
- `minimal`: 삽화 없이 문장 beat를 순차 노출하는 텍스트 UI

아이 대상 실험 배정이나 통계 수집은 포함하지 않는다. 이번 비교판은 제작자가 시각적 방향과 읽기 경험을 판단하기 위한 로컬 도구다.

## Git 및 실행

- 기준 브랜치: `feat/alice-branching-mvp`
- 실험 브랜치: `experiment/alice-ui-variants`
- 기준 서버: `http://127.0.0.1:8081`
- 비교 서버: `http://127.0.0.1:8082`

비교판 주소:

```text
http://127.0.0.1:8082/?ui=current
http://127.0.0.1:8082/?ui=visual-novel
http://127.0.0.1:8082/?ui=minimal
```

알 수 없는 `ui` 값은 `current`로 대체한다.

## 공통 불변 조건

- 기존 스토리 데이터와 장면 연결을 복제하지 않는다.
- 세 UI는 같은 `session.js` 세션과 `endingsSeen`을 공유한다.
- 주소의 `ui` 값은 관찰 기록이나 아이 성향 데이터에 넣지 않는다.
- UI를 바꿔도 현재 장면과 칩 응답 복구 상태를 유지한다.
- 설정, 낱말 패널, 복구 화면, 다시 시작의 의미와 데이터 계약은 유지한다.
- 현재 UI는 시각·동작 회귀 없이 기준선으로 남긴다.
- 모든 조작 대상은 최소 44px이며 키보드로 사용할 수 있어야 한다.
- `prefers-reduced-motion`에서는 장식 애니메이션을 정지한다.
- 외부 런타임 의존성이나 빌드 단계를 추가하지 않는다.

## UI 선택 구조

`ui-variant.js`가 URL을 읽어 다음 레코드를 반환한다.

```js
{
  id: "current" | "visual-novel" | "minimal",
  renderSetup,
  renderScene,
  renderChipResponse,
  renderEnding,
  renderRecovery,
}
```

`app.js`는 스토리 상태 전이와 저장을 계속 소유한다. UI 렌더러는 받은 상태를 HTML로 바꾸고 `data-action` 계약만 노출한다. 변형별 모듈이 세션을 직접 변경하지 않는다.

개발용 비교 메뉴는 `?compare=1`일 때만 표시한다. 메뉴는 세 URL 링크를 제공하며 일반 아이 플레이 주소에서는 보이지 않는다.

## 비주얼노벨 UI

### 화면 구조

```text
┌─────────────────────────────┐
│                             │
│       풀블리드 배경           │
│    캐릭터 스프라이트 하단      │
│                             │
├─────────────────────────────┤
│ [이름표] 캐릭터 이름          │
│ 서술 또는 대화 3~5문장        │
│ [선택지 A]      [선택지 B]    │
│  ■ ■ ■ □ □  진행 트레일      │
└─────────────────────────────┘
```

- 모바일에서는 `100svh` 세로 무대이며 배경 58%, 대화창 42%를 기본으로 한다.
- 데스크톱에서는 최대 16:10 무대를 중앙에 두되 배경은 무대 안에서 풀블리드다.
- 본문은 문단 단위로 노출한다. 문장을 채팅처럼 한 줄씩 쪼개지 않는다.
- 대화창은 불투명도 92% 이상의 어두운 패널로 그림 위에 겹친다.
- 화자 이름이 있는 장면은 캐릭터별 네임태그를 사용한다.
  - 토끼: 체리 빨강
  - 체셔 고양이: 보라
  - 모자장수: 청록
  - 애벌레: 잎 초록
  - 서술자와 결말: 짙은 회색
- 선택지는 대사체 문구를 유지한 카드 버튼이며 hover 가능한 환경에서만 `translateY(-2px)`와 그림자 변화를 준다.
- 선택지가 없는 장면에는 같은 위치에 `계속 읽기` 명령을 둔다.

### 진행 트레일

- 화면 하단에 카드 모양 5개를 고정한다.
- `setup`은 0개, 첫 장면은 1개, 중간 장면은 경로 깊이에 따라 2~4개, 결말은 5개를 채운다.
- 정확한 전체 장면 수가 아니라 현재 플레이의 5단계 리듬을 보여주는 장치다.
- 텍스트 `3/5`를 접근 가능한 이름으로 함께 제공한다.

### 이미지 자산

비주얼노벨은 생성형 래스터 일러스트를 사용한다. 배경과 인물은 하나의 스타일 가이드를 공유한다.

배경 6개:

- `rabbit-hole`: 정원과 토끼굴 입구
- `tiny-garden`: 거대한 꽃과 작은 문이 있는 정원
- `cheshire-tree`: 굽은 나무와 떠 있는 웃음
- `tea-party`: 긴 테이블과 뒤섞인 찻잔
- `giant-land`: 아래로 펼쳐진 이상한 나라
- `giant-mushroom`: 거대한 버섯 숲

결말은 해당 경로의 배경을 재사용하고 `curiosity`, `joy`, `confidence` 색조 오버레이와 빛 효과로 구분한다.

캐릭터 스프라이트 4개:

- 하얀 토끼
- 체셔 고양이
- 모자장수
- 애벌레

스프라이트는 투명 PNG로 저장하고 화면 하단에 배치한다. 표정 변형은 이번 비교판 범위에서 제외한다.

이미지는 아동용 그림책 풍의 부드러운 수채화 질감, 분명한 실루엣, 높은 명도 대비를 사용한다. 텍스트, 로고, 워터마크, 공포스러운 표현은 금지한다.

## 미니멀 텍스트 UI

### 화면 구조

```text
┌───────────────────────────────┐
│          여백                  │
│      1장                      │
│                               │
│      본문 1~2문장              │
│                               │
│             ⌄                 │
│          여백                  │
└───────────────────────────────┘
```

- 삽화와 장식 카드를 사용하지 않는다.
- 배경은 기본 크림색이며 장면마다 명도 차이가 매우 작은 색조 하나만 사용한다.
- 데스크톱 본문 열은 뷰포트의 60~70%, 최대 `44rem`이다.
- 모바일 본문 열은 88%다.
- 세리프 계열 한글 폰트 스택을 사용한다.
- 본문은 18~20px, 줄간격 1.9~2.0이다.
- 챕터 라벨은 13px의 옅은 글자로 표시한다.
- 강조색은 선택지와 키보드 포커스에 쓰는 한 색만 사용한다.

### Beat 시스템

`beat.js`가 개인화가 적용된 본문을 문장 단위로 분리하고 1~2문장씩 묶는다.

```js
createBeats(renderedBody) -> string[]
```

- 따옴표 안의 종결 부호와 줄바꿈을 보존한다.
- 빈 beat를 만들지 않는다.
- 한 beat가 120자를 넘으면 한 문장만 사용한다.
- 장면 진입 시 첫 beat부터 시작한다.
- 화면 또는 `⌄` 버튼을 누르면 다음 beat를 표시한다.
- 텍스트 선택, 낱말 버튼, 선택지 링크를 누른 동작은 beat 진행으로 처리하지 않는다.
- 마지막 beat에서만 낱말 영역과 선택지를 노출한다.
- 칩 응답과 결말도 같은 beat 규칙을 사용하되 마지막에 기존 계속·다시 시작 명령을 표시한다.

현재 beat는 세션 기록과 분리된 UI 전용 상태다.

```js
uiState = {
  minimal: {
    sceneId,
    beatIndex
  }
}
```

`sessionStorage`에 저장하여 새로고침에는 복구하지만 플레이 관찰 기록에는 포함하지 않는다. 장면 id가 바뀌면 `beatIndex`를 0으로 초기화한다.

### 선택지

- 배경, 테두리, 카드 그림자 없이 밑줄 텍스트 링크처럼 보이는 버튼을 사용한다.
- 실제 요소는 키보드와 터치 접근성을 위한 `<button>`이다.
- 세로로 배치하고 각 항목의 터치 영역은 최소 48px다.
- hover에서는 밑줄 굵기와 강조색 명도만 변한다.

### 진행 표시

- 카드 트레일을 사용하지 않는다.
- `1장`, `2장` 같은 챕터 라벨이 진행 표시 역할을 한다.
- 결말에서는 `지금까지 만난 결말 N/3`을 본문과 같은 스타일의 한 줄 텍스트로 표시한다.

## 오류 처리

- 알 수 없는 UI id는 `current`를 사용한다.
- 이미지 로딩 실패 시 장면별 배경색과 텍스트는 그대로 보인다.
- 스프라이트가 없는 장면은 배경만 보여주며 빈 이미지 자리표시자를 만들지 않는다.
- 잘못 저장된 minimal beat 상태는 현재 장면의 첫 beat로 초기화한다.
- 문장 분리가 실패하거나 본문이 비어 있으면 원문 전체를 하나의 beat로 사용한다.

## 테스트

자동 테스트:

- UI query 파싱과 잘못된 값의 `current` 폴백
- 기존 `ui.js` 계약 및 현재 UI 회귀
- 본문 문장 분리와 1~2문장 beat 묶기
- 장면 변경 시 beat 초기화와 같은 장면 새로고침 복구
- minimal 마지막 beat 이전에 선택지가 노출되지 않음
- visual novel 이름표, 카드 선택지, 5단계 트레일
- 세 UI가 동일한 `data-action`과 스토리 목적지를 제공함
- 모든 비주얼노벨 배경·스프라이트 파일이 존재함

브라우저 확인:

- 390×844와 1280×800에서 세 UI에 가로 스크롤이나 텍스트 겹침이 없음
- 같은 S00, A1, A3, B2, E1 장면을 세 UI로 전환해 비교 가능
- visual novel 배경과 스프라이트가 깨지지 않고 대화창 뒤로 배치됨
- minimal 화면 탭과 `⌄` 버튼이 beat를 하나씩 진행함
- minimal 마지막 beat 전에는 선택지가 보이지 않음
- UI 전환 후 현재 장면, 칩 응답, 결말 수집 상태가 유지됨
- reduced motion에서 hover 이외의 반복 애니메이션이 정지함

## 범위 제외

- 원격 분석과 실험 배정
- 새 이야기 장면과 결말 추가
- 음성, 자동 재생, 타이핑 효과
- 캐릭터 표정 교체
- 다크 모드
- 최종 선택 UI로 기존 MVP를 교체하는 작업
