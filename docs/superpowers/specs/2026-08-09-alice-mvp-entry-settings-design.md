# Alice MVP Entry and UI Settings Design

## Goal

앨리스 MVP의 공개 진입 주소를 하나로 정리한다. 사용자는 복잡한 쿼리 파라미터를 조합하지 않고 `/`에서 바로 사용성 테스트를 시작하며, 별도 설정 페이지에서 테스트에 사용할 UI를 선택한다.

## User-facing URLs

- `/`: 항상 사용성 테스트 흐름으로 진입한다.
- `/settings.html`: `current`, `visual-novel`, `minimal` 중 테스트 UI를 선택한다.

기존 `?ui=`, `compare=1`, `test=1` 링크는 새 화면과 README에서 제거한다. 기존 북마크를 깨뜨리지 않기 위해 파라미터 해석 코드는 당분간 유지하지만, 새 진입 흐름의 상태 원본으로 사용하지 않는다.

## Selected UI State

- 설정 페이지는 선택한 UI ID를 브라우저 저장소에 기록한다.
- 저장 키는 앱의 다른 세션 데이터와 겹치지 않는 전용 키를 사용한다.
- 저장값이 없거나 지원하지 않는 값이면 `visual-novel`을 기본값으로 사용한다.
- 저장소 읽기·쓰기 오류가 발생해도 페이지는 동작하며, 해당 실행에서는 `visual-novel`로 복구한다.
- “선택한 UI로 테스트 시작” 버튼은 저장 후 `/`로 이동한다.

## Test Flow and Renderer Responsibilities

테스트 흐름과 이야기 표현을 분리한다.

- 참가자 코드 입력, 3단계 온보딩, 기록 저장·다운로드·초기화, 설정 이동은 공통 테스트 셸의 책임이다.
- 이야기 장면, 선택지, 칩 응답, 결말은 저장된 UI에 대응하는 기존 렌더러의 책임이다.
- 테스트 모드가 특정 UI를 강제로 선택하던 현재 로직은 제거한다.
- 선택된 렌더러에 테스트 전용 화면 구현이 없는 경우 공통 테스트 셸을 사용하고, 이야기 화면은 선택된 렌더러를 그대로 유지한다.
- 테스트 화면 어디서든 설정 페이지로 이동할 수 있는 명확한 링크를 제공한다.

## Settings Page

설정 페이지는 세 UI를 이름과 짧은 설명이 있는 선택 카드로 제공한다.

- 현재형: 이야기책 형태의 전체 장면 UI
- 비주얼노벨: 게임 프레임과 대화 중심 UI
- 미니멀 텍스트: 문장 단위 집중 읽기 UI

현재 저장된 선택을 처음부터 표시하고, 저장 및 시작 동작은 키보드와 화면 읽기 도구로 사용할 수 있어야 한다. 설정 페이지는 MVP 실행에 필요한 기능만 포함하며 미리보기 이미지나 추가 테마 설정은 포함하지 않는다.

## Main Entry Behavior

`/`는 쿼리 파라미터가 없어도 기존 `test=1`과 같은 참가자 테스트 흐름을 시작한다. 저장된 UI 선택은 이야기 렌더러 결정에만 사용한다. 이전 테스트 기록 복원, 참가자 교체, JSON 내보내기 동작은 유지한다.

## Error and Compatibility Behavior

- 알 수 없는 UI ID: `visual-novel`로 폴백한다.
- 저장소 접근 실패: 메모리 기본값 `visual-novel`을 사용한다.
- 기존 `?ui=` 링크: 앱은 열리지만 저장된 설정을 우선한다.
- 기존 `?test=1` 링크: `/`와 동일한 테스트 흐름으로 동작한다.
- `compare=1`: 비교 메뉴를 더 이상 표시하지 않는다.

## Documentation

README는 공개 주소를 `/`와 `/settings.html` 두 개로만 안내한다. 기존 UI 비교판 URL 목록과 쿼리 조합 설명을 제거하고, 설정 페이지에서 UI를 선택하는 절차로 교체한다.

## Verification

- 설정 저장소의 정상값, 잘못된 값, 접근 오류 폴백 단위 테스트
- 설정 페이지가 세 UI 선택지와 현재 선택, 시작 링크를 제공하는지 테스트
- `/`가 파라미터 없이 테스트 흐름을 시작하는 통합 테스트
- 선택한 세 UI 각각에서 이야기 화면이 해당 렌더러로 출력되는 통합 테스트
- 공통 참가자 입력·온보딩·다운로드·초기화가 모든 선택에서 유지되는 회귀 테스트
- 기존 `?test=1` 호환과 `compare=1` 메뉴 제거 테스트
- README의 공개 URL이 두 개로 정리되었는지 정적 검사

## Out of Scope

- 서버 측 라우터 또는 빌드 도구 도입
- UI별 별도 테스트 데이터 스키마
- UI 미리보기 이미지 생성
- 기존 저장된 이야기 세션 형식 변경
- 실제 배포 도메인 결정
